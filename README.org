#+TITLE: Leman.el

A Matrix client for GNU Emacs.

Leman grew out of [[https://github.com/alphapapa/ement.el][ement.el]] and is developed as an independent project:
same GPL heritage, new design.

* Features

+ Rooms: message history, HTML rendering, avatars, images, spoilers
+ Replies and [[https://github.com/matrix-org/matrix-spec-proposals/pull/3440][threads]] (MSC3440)
+ Reactions, including custom server emoji rendered as images
+ Read receipts and typing indicators
+ Desktop notifications (mentions, calls, etc.)
+ Room lists: sidebar-friendly buffers, spaces, room directory
+ Org-based message composition
+ End-to-end encryption via the bundled Rust agent (see below)

* Requirements

+ Emacs 30.1 or later
+ A Matrix homeserver
+ For E2EE: [[https://rustup.rs][Rust]] (to build the agent once) and ~curl~

* Installation

With =package-vc= (Emacs 29+):

#+begin_src elisp
  (package-vc-install "https://github.com/thargosu/leman.el")
#+end_src

Then:

#+begin_src elisp
  M-x leman-connect
#+end_src

* End-to-end encryption

E2EE is provided by ~leman-agent~, a small Rust subprocess wrapping
the [[https://github.com/matrix-org/matrix-rust-sdk][matrix-sdk-crypto]] state machine (Olm/Megolm, vodozemac).
Communicating over a line-delimited JSON protocol on stdio, it keeps
key material out of Emacs and crash-isolates the crypto (see
~e2ee/PROTOCOL.org~).

Build it once:

#+begin_src sh
  cd e2ee/agent && cargo build --release
#+end_src

Or from inside Emacs with ~M-x leman-e2ee-build-agent~ (requires
cargo on the ~exec-path~).  If the agent isn't found at connect
time, a warning is shown; ~M-x leman-e2ee-status~ reports whether an
agent is running and where the program was looked up.

Current support:

+ Decryption of encrypted rooms, including history after key receipt
+ Encryption of outgoing messages, with automatic key distribution to
  member devices (fails closed: encrypted rooms never receive
  plaintext, and unencrypted rooms are unaffected)
+ Automatic key uploads, device list tracking, key claiming
+ Room keys and sessions persisted in a local SQLite store
  (~$XDG_DATA_HOME/leman/crypto/~)

+ Emoji SAS device verification (~M-x leman-e2ee-verify~): after
  verifying, other clients' "device not verified" warnings go away

Not yet (planned, see ~ROADMAP.org~): key backup, and encrypting
reactions in encrypted rooms.

* Upgrading (package-vc)

#+begin_src elisp
  M-x package-vc-upgrade RET leman RET
  M-x leman-e2ee-build-agent   ; the agent binary is not rebuilt by package-vc
#+end_src

Leman warns at agent start when the binary is older than its source.
Do not patch the installed clone in place: local changes make
`package-vc-upgrade' refuse to pull.

* Development

#+begin_src sh
  # Rust agent: tests, coverage, lint, audit
  cd e2ee/agent && cargo test && cargo llvm-cov --cobertura --output-path cobertura.xml && cargo clippy -- -D warnings && cargo audit

  # Elisp: tests
  emacs --batch -Q -L . -l tests/leman-tests.el -f ert-run-tests-batch
#+end_src

Every push runs the full pipeline (tests, coverage, clippy, RustSec
audit, SonarCloud analysis) on GitHub Actions.

See ~ROADMAP.org~ for plans (E2EE phases, UI rework) and
~e2ee/PROTOCOL.org~ for the agent protocol specification.
